# PR #53 レビュー対応仕様: date anchor 補正の戻り値拡張と force の上書き検証

`.github/reports/pr-53-review.md` の指摘 [P1]#2 / [P2]#1 / [P2]#2 / [P3] への対応。
計画・タスクは `tasks/pr_53/overview.md` / `tasks/pr_53/tasks.md`。
前提仕様（force の目的・ゲート）は `specs/2026-11-06-spec.md`（Issue #50）を継承する。

## 1. `apply_date_anchor_normalization` の戻り値拡張（P2#1）

### 背景

従来の戻り値は `Optional[tuple[int, int]]`（成功 = offset / 失敗 = None）で、
None の理由（DB 未指定・テンプレなし・date 候補 0 件 等）が区別できなかった。
そのためサービス経路では「anchor 解決不能以外の理由」でも force が発火しうる状態だった。

### 変更後の戻り値

```python
def apply_date_anchor_normalization(...) -> tuple[bool, str | tuple[int, int]]:
```

- 成功: `(True, (offset_x, offset_y))`（従来の offset 返却を保持）
- 失敗: `(False, <REASON>)`

失敗理由はモジュール定数で公開（`app/date_anchor.py`）:

| 定数 | 意味 | force 発火 |
|------|------|-----------|
| `NO_DB` | db_path なし | 否 |
| `NO_DATE_OR_CLINIC` | structured date / clinic なし | 否 |
| `NO_TEMPLATE` | クリニック未学習 | 否 |
| `NO_DATE_COORDS` | template の date 未学習（shift 失敗時含む） | 否 |
| `NO_OCR_ENTRIES` | OCR エントリ空 | 否 |
| `ANCHOR_UNRESOLVED` | **date 候補 0 件 / 曖昧で解決不能** | **是** |
| `NOT_NORMALIZED` | 再正規化失敗 | 否 |

### force 発火条件の限定（両経路共通）

`image_processing_service.py` / `receipt_processor.py`:

```python
anchor_ok, anchor_detail = apply_date_anchor_normalization(...)
if not anchor_ok and anchor_detail == ANCHOR_UNRESOLVED:
    apply_date_basis_force(...)
```

`anchor_result is None` の広い条件は廃止。spec の「date 候補 0 件等で解決不能」に一致させる。

## 2. `apply_date_basis_force` の上書き検証と戻り値 bool 化（P1#2 + P3）

### 背景

force は raw の絶対座標に template の `coords_corrections` を直接当てる（案A）。
フレームがずれている画像では、ずれた位置の文字列を name / amount として拾い、
structured と DB へ**無条件上書き**するリスクがあった（医療費控除の申告データに直結）。

### 変更後の仕様

```python
def apply_date_basis_force(...) -> bool:
```

- **近傍一致の有無**: `search_fields_by_proximity` が閾値内で返したフィールドのみ候補になる
  （閾値内に box がなければ候補にすら入らない。既存挙動の明示化）。
- **既存非空値の保守**: `structured[field]` に既存の**非空**値があり、抽出値と**異なる**場合は
  **上書きしない**。上書きするのは「既存値が空 / None」または「抽出値 == 既存値（no-op）」のみ。
  - 効果: force は「**空欄を埋める**補助」に限定される。anchor 未解決時に既存値が誤っている
    場合の自動修正は行わない（安全側）。既存値の誤りは Web UI のユーザー修正に委ねる。
- **戻り値**: structured を 1 件以上更新したら `True`、それ以外（ゲート不通過・抽出ゼロ・変化なし）は
  `False`。紛らわしかった `(0, 0)` / `None` の返却は廃止。
- `proximity_threshold == 50.0` の分岐を削除（引数既定値 50.0 と `DEFAULT_PROXIMITY_THRESHOLD` 同値のため）。
- ゲート（clinic 非空 / `coord_basis=='date'` / date 学習済み / DB 指定）と
  DB 同期（`update_receipt_ocr_json_by_source` のみ・insert なし）は従来どおり。

### フロー（更新後）

```
apply_date_anchor_normalization(raw, structured, db, output_dir)
  -> (True, (offset_x, offset_y))   -> 通常の date 基準パス（force 不発）
  -> (False, ANCHOR_UNRESOLVED)     -> apply_date_basis_force(...)（date 候補 0 件等のみ）
  -> (False, <その他の理由>)         -> force 不発
       gate: clinic 非空 && template.coord_basis=='date' && coords_corrections.date 学習済み
       -> search_fields_by_proximity(entries, coords, threshold)
       -> date 以外のフィールド: 既存非空値と異なる場合は上書きしない（空欄のみ埋める）
       -> 1 件以上更新時のみ: OutputWriter().write(...) + update_receipt_ocr_json_by_source(...)
       -> 戻り値 bool（更新有無）
```

## 3. `verify_date_anchor --force` との関係

`verify_date_anchor.py` は `apply_date_basis_force` を呼ばず force 抽出を独自実装しているが、
「報告のみ・元ファイル/DB 不変更」設計のため P1#2 の上書き検証が効かないことは許容する
（本対応のスコープ外。必要なら別 Issue で統一検討）。
