# Issue #42 仕様: coord_basis の手動切替（topmost → date）を Web UI に追加

ブランチ `feature/converts-coord-basis/42`、実装で追加した仕様。本ドキュメントはその振る舞い仕様。実装と整合する。
（動作詳細の更新頻度の高い箇所は `.hermes/rules/coordinate-normalization.md` を参照。）

## 背景・目的

Issue #39 の date 基準による座標正規化は、template の `coord_basis` を自動で `'topmost' → 'date'` へ遷移させる設計だった。
実データ検証（`data/verify-01.db` の `なの花薬局札幌二十四軒店`）で、この自動遷移が

- 1 レシート内に date 候補が 2 件（例:「調剤日」「発行日」）あり `resolve_date_anchor()` が曖昧と判定 → `len(within)==2` → None → **遷移しない**

ために、`coord_basis` が常に `'topmost'` のままになることが確認された。

検証段階のアプリであるため、本 Issue は **Web フォームから手動で coord_basis を topmost → date へ切り替え**、
date 基準による補正（前方補正・座標検索）の挙動を検証可能にすることを目的とする
（自動遷移の根本原因である曖昧性判定の緩和は後続 Issue の対象とし、本 Issue は検証手段の提供に留める）。

## 用語

| 語 | 定義 |
|----|------|
| coord_basis | `templates` の座標基準識別列。値は `'topmost'`（従来）または `'date'`（#39 移行済み） |
| 手動切替 | Web admin 画面から `POST /admin/templates/{clinic_id}/basis` を呼び、最新 template を topmost → date に一方向で移行すること |
| date box 学習済み | `coords_corrections['date']` が `is not None`（date_anchor.py の既存判定と同一） |

## 対応方針（確定: Q1=案A, Q2=案A）

本 Issue の設計時相談事項は推奨どおり以下の案で確定した。

- **Q1（切替ビジネスロジックの置き場所）= 案A**: `app/services/template_admin_service.py` に新設 `TemplateAdminService`。
  server.py は薄いルーティングのみ（SRP / DI 規約に準拠）。
- **Q2（template シフト計算の共通化）= 案A**: `app/coord_normalizer.shift_template_to_date_basis()` を新設し、
  自動遷移（`date_anchor.apply_date_anchor_normalization`）と手動切替（admin）の**両方**から呼ぶ。
  シフト意味論（「template 自身の date box の min-x/min-y を原点に」）を 1 箇所に集約する。
  **検証用途の本 Issue では、手動切替と自動遷移で coords が一致することが重要**。

### シフト意味論（クリティカル）

`shift_template_to_date_basis(coords)` は **template 自身の date box の min-x / min-y** をオフセットに全 box をシフトする
（**raw の anchor offset ではシフトしない** — Issue #39-4）。raw anchor でシフトすると template の date box が原点に
揃わず、以降の近傍検索・座標マッチングが継続してずれるため。

- date box 未学習 / 不正（2D 座標でない）→ `None` を返し、呼び出し側はガード（409）する。
- 不正座標への防御として、date box の点が数値（int/float、bool を除く）であることを検証する
  （`_is_numeric_point`）。計画時コードは `[["x","y"]]` で `int - str` の TypeError を起こすため追加。

## エンドポイントとガード（HTTP マトリクス）

`POST /admin/templates/{clinic_id}/basis`（body `{"basis":"date"}`）

| 条件 | HTTP | レスポンス |
|------|------|-----------|
| `db_path` 未設定（DB なしで create_app） | 503 | "DB が設定されていません"（管理機能は DB 必須。JSON-only フォールバックに依存しない） |
| `basis != 'date'`（未対応値・欠落） | 400 | InvalidBasisError |
| clinic_id 不明 | 404 | 要 `get_clinic_by_id()`（今回 db.py に追加。template 未学習の 409 と区別） |
| clinic 存在・template 未学習 | 409 | "テンプレート未学習のため切替できません" |
| 既に `coord_basis=='date'` | 200 | `{"status":"noop","reason":"already_date"}` — 冪等。`template_history` に追記しない |
| date box 未学習 / coords 不正 | 409 | "date box 未学習のため切替できません"（**必須ガード** — 未学習 template を強制 date 化すると前方補正が崩れる: Issue #40） |
| 移行成功 | 200 | `{"status":"updated","coord_basis":"date"}` — `change_reason='manual_basis_toggle'` で history を 1 件追記 |
| 競合（read と update の間に他経路で移行済み） | 200 | `update_template_basis()` が False → no-op として扱う |

一覧 `GET /admin/templates` は `db.get_all_templates_with_names()` を整形表示（clinic 名 join・最新版のみ・coords デコード済み）。
date box 学習有無と coord_basis を表示し、切替フォームは「date box 学習済み かつ 未移行」の clinic のみ表示する。

## 再利用した既存ビルディングブロック（再実装しない）

- `app/db.update_template_basis(db_path, clinic_id, new_coords, changed_fields, history_reason) -> bool` —
  1 トランザクションで「移行前 coords を history にスナップショット → coords 差し替え → `coord_basis='date'`」。
  **「template なし」「既に date」の両方で False**（二重変換ガード内蔵）。404/409/noop の区別は呼び出し側で template を先に読む。
- `app/db.get_latest_template_by_clinic()` / `get_all_templates_with_names()`
- `app/coord_normalizer.shift_template_coords()`（単一 box・multi box を同一オフセットでシフト）

## 冪等性と二重変換ガード

- `update_template_basis()` は内部で「既に date なら False（no-op）」。サービスはその前に template を読み、
  既に date なら要求自体を `noop` として早期返却。
- どちらの経路でも `template_history` への追記は **topmost のとき 1 回のみ**（`change_reason='manual_basis_toggle'`）。
