# Issue #50 仕様: date anchor による補正の強制

`templates.coord_basis` が `date` のクリニックで、クリニック名抽出に成功したにもかかわらず
date anchor 補正が実行できない（`resolve_date_anchor` が date 候補 0 件で `None` を返す）ケースでも、
テンプレートの `coords_corrections` を使って強制的に座標ベースの抽出（name / amount）を試みる機能。

## Issue #50 受入要件1の確認（2026-11-06）

- 結論: 現状機能は「coord_basis=date でも date anchor 補正には topmost からの date 座標値の特定が必須」という
  Issue の結論と齟齬がない。
- 根拠: `app/date_anchor.py` `apply_date_anchor_normalization()` は `find_date_candidates`（date 候補 0 件なら []）
  → `resolve_date_anchor`（None、date_anchor.py:305-306 の早期 return）→ そのまま `None` を返す。
  raw は topmost のまま、再正規化も座標抽出も走らない。
- 対応: 差し戻しなし。本 Issue で「日付 box を特定せず coords を当てはめて強制抽出」する拡張
  （`apply_date_basis_force()`）を実装する。

## 設計判断

- **強制抽出の方法（案A採用）**: date 基準 template の `coords_corrections` に対して
  `search_fields_by_proximity` を適用し（`_apply_coordinate_extraction` の延長）、
  raw の box を近傍抽出して name / amount を取得する。**再正規化は行わない**。
- **force ゲート（受入要件3）**: `coord_basis == 'date'` **かつ** `structured.clinic` 非空（クリニック名抽出成功）
  **かつ** template の `coords_corrections` に date が学習済み。low_confidence 時と
  `apply_date_anchor_normalization` 成功時（anchor 確定）は通常パスに任せ、force は補完としてのみ発動。
- **structured 反映・二重登録防止**: `_apply_coordinate_extraction` と同様、structured を in-place 更新 +
  `OutputWriter.write` で `*-structured_data.json` を書き直す。`insert_receipt` は呼ばない。
  DB の OCR 座標同期は `update_receipt_ocr_json_by_source`。
- **date 未学習 template は対象外**（受入要件3 の趣旨・#40 ガードと整合）。

## フロー（画像OCR / watcher 両経路）

```
apply_date_anchor_normalization(raw, structured, db, output_dir)
  -> (True, (offset_x, offset_y)) -> 通常の date 基準パス（force 不発）
  -> (False, ANCHOR_UNRESOLVED)   -> apply_date_basis_force(raw, structured, db, output_dir)
       gate: clinic 非空 && template.coord_basis=='date' && coords_corrections.date 学習済み
       -> search_fields_by_proximity(entries, coords)
       -> date 以外のフィールド: 既存非空値は上書きしない（空欄のみ埋める / PR #53 レビュー P1#2）
       -> 更新 1 件以上時のみ OutputWriter().write(output_dir, raw_path, structured)
       -> update_receipt_ocr_json_by_source(db, raw_path, entries)
       -> 戻り値 bool（更新有無）
  -> (False, <その他の理由>)       -> force 不発（PR #53 レビュー P2#1 で限定）

※ 戻り値仕様・上書き検証の詳細は specs/2026-11-09-spec.md を参照。
```
